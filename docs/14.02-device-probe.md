# 14.02 device prerequisite check

The isolated `/u2/` page requires a button press on a PS4 running firmware
14.02. It then navigates once to the existing host's userland ROP setup and
calls `probeAfterglow`. A session marker is consumed before the browser memory
step, so restoring or refreshing the work page cannot repeat the probe.

The check asks the system for its loaded modules and memory map, verifies
libc gadgets and unused executable room, opens ordinary device nodes and
APM clones, checks numbered APM units, pins and restores CPU affinity, and
measures socket calls. A fresh-socket canary uses the same option request as
the exploit and records its first return value and errno. It does **not** fire
the APM use-after-free,
read or write kernel memory, run the bootstrap, or load HEN or GoldHEN. It
can still close or hang the browser because it uses the WebKit primitive and
userland ROP.

The page saves a short stage and final result in browser storage. Reopening
`/u2/` shows that result. A PASS means only that these device prerequisites
were available on this console. The socket allocation effect remains unverified
even if calls return zero. It does not prove the kernel exploit works or
make the 14.02 GoldHEN launcher safe.

The first 14.02 hardware run reached native ROP, opened 20 APM clones and
126 UDP sockets, and restored CPU affinity. The initial probe then reported
0/126 successful *repeat* option calls. That check was invalid: the probe
had already called the option on those sockets, used a blank address unlike
the exploit, and did not establish whether repeat calls should succeed.
The corrected probe measures a first call separately and treats its return
as an observation rather than a compatibility verdict. In the second 14.02
hardware run, the first exact-request option call returned 0 and the last
call in each of three timed batches returned 0. All 126 UDP sockets were
created. The remaining kernel allocation and UAF behavior were not tested.

The check holds APM clone descriptors until the browser process exits. A
clone is freed on close, which can consume one of the units used by a later
exploit attempt. **Cold reboot the 14.02 console after the check and before
any later exploit attempt.** The normal 14.02 GoldHEN launch remains disabled.

Run `node tests/u2-probe-selftest.cjs` to verify the one-shot gate, the
probe branch, and truthful PASS/BLOCKED classification.
