# 14.02 kernel diagnostic design (offline only)

This is a design for collecting the missing retail 14.02 kernel values. There
is no browser route, import, launch control, or deployable binary for it. The
current 14.02 GoldHEN path remains blocked after a hardware kernel panic.

## Intended data

Capture the unmodified 48-byte `sysent` records for syscall numbers 11,
197–201, 384–389, 394, 409–411, 500, and 591 (18 records). For 384–389,
394, and 409–411, read the 14-byte prologue at each record's original
`sy_call` target (10 handlers). Also capture the complete bootstrap and host
patch windows, the 200-byte teardown padding, and the original VM mapping
rights and probe file operation-table pointer. Record the kernel-base-relative
address for each handler and the exact raw bytes. Reject null, noncanonical,
out-of-text, or unreadable handler pointers.

The full stock `sysent[11]` record must be captured **before** the bootstrap:
the bootstrap changes its `sy_narg`, `sy_call`, and `sy_thrcnt` fields. The
available reference image has zeroed syscall data and cannot supply these
bytes. A later gate read of `sysent[11]` is already a modified state.

## Required state transitions

| State | Action and evidence required to advance | Failure action |
| --- | --- | --- |
| Browser ready | Persist a run ID and stage; verify storage readback. | Stop without firing the exploit. |
| Before UAF | Validate firmware, userland gadgets, spare executable room, and syscall stubs. | Stop without firing the exploit. |
| Kernel base known | Record the independently checked base and UAF shot count. From the first UAF shot onward, APM and kqueue handles may be hazardous. | Keep browser process open; cold boot. |
| Stock captured | Read all fixed windows and full stock `sysent[11]` before any kernel write. Classify bootstrap sites globally. | Keep browser process open; cold boot. |
| Dynamic takeover | Verify current VM rights and probe `f_ops`, then widen the mapping and hook the probe. Read both values back. These are kernel writes **before** bootstrap preflight. | Keep browser process open; cold boot. |
| Bootstrap returned | Run the guarded bootstrap. Capture ioctl return and errno immediately, before writing its scratch area. Only an explicit success status permits the next state. | Do not call `openRing0`, another UAF shot, close, or reload. Cold boot. |
| Gate live | Verify RWX transition, syscall 11 thread, kernel base, and the original probe `f_ops` restoration with readback. | Keep browser process open; cold boot. |
| Handles defused | Clone and verify complete operation tables; verify every APM and queue `f_ops` points to its safe copy, every queue note-list high word is zero, and every write reads back. | Keep browser process open; cold boot. |
| Stock data complete | Read the remaining 17 syscall records and 10 handler prologues through the gate. Persist a complete, checksummed local export and verify every chunk. | Report incomplete data; cold boot after cleanup. |
| Finished | Display the export result. Do not load a HEN or GoldHEN thread. Reboot the console to clear the diagnostic kernel changes. | Cold boot. |

The current `teardown()` is not proof of the “Handles defused” state: it only
checks the cloned tables' `fo_close` field, can report success with queues
unmoved, and does not read back every queue note word. Its success return
cannot be used as permission to close the diagnostic page.

The current host also ignores the bootstrap ioctl return, overwrites its
scratch area, and attempts a further UAF shot when gate setup fails. A
guarded bootstrap cannot be substituted for the old bytes without rewriting
that control flow. Refusal after the dynamic takeover leaves the probe file
hooked and no syscall 11 cleanup gate. No safe return from that state has been
demonstrated.

## Export boundary

Keep captured bytes local to the console until the user selects a transfer
method. Use versioned, chunked browser storage with a manifest, length and
checksum, synchronous write/readback, and a complete/incomplete flag. The
existing two-slot breadcrumb is for short stage names, not the roughly
1 KB of syscall and handler data. Do not upload raw kernel bytes or device
data to a public GitHub repository as part of the diagnostic.

## Review gates before any console test

The bootstrap's syscall activation order was corrected offline, but its
machine code and integration still need independent review. Disabling
interrupts on one CPU does not stop other cores from executing kernel text
while it changes. A kernel-only run can still panic or require a cold boot;
it must be presented to the operator as such. The 14.02 GoldHEN launch remains
blocked until the collected values support separate guards for the loader,
host patch pass, and GoldHEN's own fixed writes.
